# Reference

> **If you have just taken over the website, do not start here.** Start with
> [**`../SECRETARY.md`**](../SECRETARY.md) — the whole ordinary job, in one page,
> with nothing in it about servers.
>
> This folder is the layer underneath: it exists for the day something has gone
> wrong, or for somebody changing how the site works. **None of it is needed for
> ordinary club business.** Adding a trip means adding a Google Calendar event,
> and nothing in this folder is involved.

The documentation is three layers, and each fact lives in exactly one of them:

| Layer | File | For |
|---|---|---|
| 1 | [`../SECRETARY.md`](../SECRETARY.md) | the officer's manual. Edit, check, preview, publish |
| 2 | [`../README.md`](../README.md) | how the site is built, and why |
| 3 | this folder | access, machines, deployment, history |

---

| If you want to | Read |
|---|---|
| Work on the code, the design or the tools — clone, run and test locally | [DEVELOPER.md](DEVELOPER.md) |
| Get an account and a key so you can publish at all, or hand access over when you leave | [ACCESS.md](ACCESS.md) |
| Publish the site, or fix a deploy that went wrong | [DEPLOY.md](DEPLOY.md) |
| Know what machine the site runs on, where the files go, and who may write to them | [SERVERS.md](SERVERS.md) |
| See what happened last time somebody deployed | [DEPLOY-LOG.md](DEPLOY-LOG.md) |
| Understand why the site is hosted this way, or argue for changing it | [HOSTING.md](HOSTING.md) |
| Write anything that appears on the site | [WRITING.md](WRITING.md) |

**`SERVERS.md` and `DEPLOY-LOG.md` go stale first.** Both are written as records
with dates on them, so when a fact is wrong it is visibly old rather than
quietly wrong. If you look something up and the file disagrees with reality, fix
the file. That takes a minute and saves the next person an afternoon.
